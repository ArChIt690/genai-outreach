# GenAI Fund outreach prototype

This prototype supports a small, accountable outreach workflow: discover relevant AI and robotics people from public X posts, inspect why they match, prepare a message grounded in evidence, approve its exact text, and track a consenting test conversation. The implementation is deliberately limited to one operator and one active sender so that the full workflow remains understandable and usable without developer assistance.

The application uses Python, FastAPI and server-rendered Jinja templates, with PostgreSQL as its durable state store. Official X APIs handle account authorization, public discovery, direct messages and conversation reads. Segment search retrieves a bounded recent sample and deduplicates people by stable X user ID. A transparent heuristic distinguishes topic relevance, public role signals and first-person building or research evidence. It does not treat follower count as professional quality or infer location from a person's name.

Personalization starts from selected public source material. The baseline template attributes a post directly and incorporates the operator's stated purpose. An optional model adapter can improve wording, with structured source checks and a visible template fallback. Source validation cannot establish every semantic claim, so the interface keeps evidence beside the draft for human review. Private direct messages and OAuth credentials are excluded from model input.

The most important engineering decision concerns sending. An approval records the exact draft version, content hash, sender, recipient, purpose, consent and selected evidence. Editing or regenerating invalidates that approval. Before dispatch, the server rechecks eligibility, reserves an immutable attempt under database locks, commits it, and calls X once. If a response is lost after X may have accepted the message, the outcome remains unknown and resending is blocked. Only unique positive conversation evidence can reconcile it as sent. This avoids presenting ordinary HTTP retries as reliable message delivery.

Discovery and contact permission remain separate. The assessment build sends only to deployment-allowlisted controlled or explicitly consenting test accounts. It checks available history and maintains a durable contact ledger across reconnects. An incoming reply after the confirmed send creates an attention item; earlier consent messages do not count as outreach replies. Explicit opt-outs create suppression records without triggering another automatic response.

Verification includes real PostgreSQL concurrency tests, mocked provider contracts, failure and recovery scenarios, and a browser walkthrough on desktop and mobile. AI development assistance generated implementation and tests, which were checked with those tools and source review; the candidate must also personally understand and validate the work. Live X account compatibility remains unverified in the development workspace and must be demonstrated before claiming full completion.

Costs are bounded through small searches, limited drafts and conservative local usage reservations. Template drafting has no external model cost; actual X/model charges depend on the configured accounts and current provider pricing. Documented limitations include seven-day discovery, thirty-day DM history, manual synchronization, and no bulk campaigns, automated follow-ups or encrypted Chat subsystem. Next steps are the controlled live send/reply verification, a cold setup trial on the evaluator's environment, and the required recorded demonstration.
