## 2. What was built (one paragraph)

It's a **Python web app** (FastAPI + server-rendered HTML pages + PostgreSQL). A single operator logs in with a password. The operator:
- searches X's recent public posts by topic,
- sees a ranked list of people with a score out of 10 and the reasons behind it,
- opens a person to see their actual posts next to a message editor,
- drafts a message (from a template that quotes their post, or optionally from Claude),
- approves the **exact text**,
- sends it,
- syncs replies, and sees "Needs attention" when someone replies.

The app has two modes:
- **Fixture mode**: fake people, fake posts, fake sending, all stored locally. No real X calls. **This is the only mode that has been tested.**
- **Live mode**: real X API calls through OAuth. **This has never been run.** No X credentials were used.

The code is very cautious. Most of it exists to prevent duplicate sends, stale approvals and unsafe actions.

### 5.2 `app/` core

**`app/config.py`**: the `Settings` class. Every env var lives here. The important ones:

| Setting | Default | Meaning |
|---|---|---|
| `APP_MODE` | `fixture` | `fixture` (fake) or `live` (real X) |
| `DATABASE_URL` | local postgres | Must be `postgresql+psycopg://` |
| `OPERATOR_PASSWORD_HASH` | empty | Argon2 hash of the login password |
| `TOKEN_ENCRYPTION_KEY` | empty | Fernet key for encrypting X tokens |
| `SEND_ENABLED` | `false` | Master switch for sending |
| `X_CLIENT_ID` / `X_CLIENT_SECRET` | empty | From the X developer portal |
| `X_CALLBACK_URL` | `…/oauth/x/callback` | Must equal `APP_ORIGIN + /oauth/x/callback` |
| `TEST_RECIPIENT_IDS` | empty | **Comma-separated numeric X IDs. In live mode these are the ONLY people who can be messaged.** |
| `HISTORY_LIMIT_ACKNOWLEDGED` | `false` | Confirms you understand X only shows 30 days of DM history |
| `X_BUDGET_USD` / `MODEL_BUDGET_USD` | 5 / 1 | Local spend caps |
| `DAILY_SEND_LIMIT` | **10** (was 2) | Max send attempts per UTC day |
| `DRAFT_PROVIDER` | `template` | `template`, `gemini` or `anthropic` |
| `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL` | empty | Only used if the provider is `anthropic` |

It also validates its own values: non-localhost origins must use HTTPS, only Postgres is accepted, and the callback URL must match.

**`app/db.py`**
- `make_database(url)` creates the SQLAlchemy engine and session factory.
- `workspace_lock(db)` locks the single `workspaces` row with `FOR UPDATE`. **Almost every write operation takes this lock first**, so actions run one at a time. That's how races are avoided.
- `initialize_workspace` creates the workspace row and **refuses to start if the DB was created in the other mode** (`MODE_MISMATCH`). Fixture data and live data can never share a database.

**`app/models.py`**: the 14 tables:

| Table | Holds |
|---|---|
| `workspaces` | One row (`id="main"`): mode, paused flag, sender name, **purpose** text + version, spend counters |
| `operator_sessions` | Login sessions (token hash, CSRF token, expiry, temporary OAuth state) and drafts used this session |
| `accounts` | Connected X sender account: encrypted access/refresh tokens, `active_attempt` (a send in progress), rate-limit cooldown |
| `search_runs` | Each search: the query sent to X, its terms, post count, and whether results were capped |
| `candidates` | People found: X ID, handle, name, bio, location |
| `search_results` | Person ↔ search, with **score** and **reasons** (JSON) |
| `evidence` | The person's actual posts used as evidence: text, URL, content hash, still available or not |
| `consents` | Test-consent records: who, reference, expiry (7 days), revoked |
| `outreach` | **One row per sender+recipient pair (unique).** Draft text, version, approval hash/snapshot, send status, conversation ID, sync state. This is the "never double-message" ledger. |
| `send_attempts` | Each send attempt: request key (unique), exact text, status (`in_flight` / `sent` / `rejected` / `unknown`) |
| `dm_events` | Imported DM messages (unique on account + X event ID, so no duplicates) |
| `suppressions` | Do-not-contact list (manual, or automatic when someone replies "STOP") |
| `usage` | Cost reservations and settlements |
| `audit` | Log of every important action |
| `fixture_messages` | Fake X inbox used only in fixture mode |

**`app/security.py`**
- `password_hash` / `verify_password`: Argon2.
- `cipher(settings)`: Fernet object for encrypting and decrypting tokens.
- `new_session`: random cookie token. Only its **SHA-256 hash** is stored in the DB, plus a CSRF token.
- `session_for(request)`: reads the `operator` cookie and raises `LOGIN_REQUIRED` if it's invalid or expired.
- `csrf_check`: rejects POSTs with a wrong `Origin` header or a wrong CSRF token.

**`app/errors.py`**
- `DomainError(code, message, status)`: a business rule blocked something (e.g. `CONSENT_REQUIRED`). Shown on the error page.
- `ProviderError`: X failed. `definitive=True` means X clearly said no. `False` means "we don't know if it went through".

**`app/main.py`**: builds the app.
- On startup it initialises the workspace, creates the fake sender account in fixture mode, and runs `recover_stale` (any send stuck as "in flight" becomes "unknown").
- A middleware adds strict security headers (CSP, no framing, no caching) and rejects bodies over 32 KB.
- GET pages: `/` → `/discover`, `/login`, `/healthz`, `/readyz`, `/settings`, `/discover`, `/candidates/{id}`, `/activity`, `/privacy`.
- Error handlers: `DomainError` shows `error.html`, and `LOGIN_REQUIRED` redirects to `/login`.

**`oauth.py`**: "Connect with X" using **OAuth 2.0 with PKCE**.
- `/oauth/x/start`: makes a random `state` and `verifier`, stores them (the verifier encrypted) on the session, and redirects to `x.com/i/oauth2/authorize` with the scopes `tweet.read users.read dm.read dm.write offline.access`.
- `/oauth/x/callback`: checks `state`, uses it once only (so it can't be replayed), exchanges the code for tokens, checks all scopes were granted, calls `/2/users/me`, and saves the **encrypted** tokens. Only one account can be connected at a time.

### 5.4 `app/services/`: the business logic

#### `discovery.py`: finding people
1. `build_query("robotics, embodied AI", roles, location)` builds an X search string such as
   `("robotics" OR "embodied AI") ("founder" OR "researcher") -is:retweet lang:en`.
   It allows at most 5 terms and blocks X operators like `from:`, so users can't inject them.
2. `discover()` calls X **recent search** (last 7 days, **max 50 posts**), groups posts by author, skips protected accounts and yourself, and scores each author.
3. `score_candidate()` gives a **heuristic score out of 10**:
   - **Topic evidence**: 2 points per matched term, max 4
   - **Building/research evidence**: 3 points if a post matches phrases like "I'm building", "we released", "our lab"
   - **Role evidence**: 2 points if the bio contains researcher / founder / engineer / developer
   - **Recent activity**: 1 point if a post is under 7 days old
   Each point has a reason stored, which is how the app "explains why they fit".
4. It keeps the **top 20 people**. Their up to 3 posts are saved as `evidence`, with a content hash.
5. `revalidate(ids)` re-fetches posts. If a post was **deleted or edited**, every approval that used it is invalidated (`EVIDENCE_CHANGED`).

#### `drafting.py`: writing the message
- Requires **score ≥ 4** and some evidence. Otherwise you get `EVIDENCE_REQUIRED`.
- Revalidates the evidence first.
- Limit: **10 drafts per login session**.
- **Default template** (no AI):
  `Hi {name}, your public post says: "{first 180 chars of post}" I'm {sender}. {purpose} Would you be open to a brief conversation? Reply STOP if you would prefer no further contact.`
- **Optional Anthropic (Claude) mode**, live mode only, and only if a key, a model and the data-use acknowledgement are all set:
  - sends only name, bio, sender, purpose and posts (never DMs or tokens),
  - asks for JSON `{draft_text, claims:[{source_id, quote}], uncertainties}`,
  - `validate_generated` checks **every quote actually appears in the cited post**, so the model can't invent evidence,
  - on any failure it **falls back to the template** and shows that it did,
  - reserves $0.10 of budget per call.
- Caches the draft: same inputs give the same draft without a new model call.

#### `outreach.py`: drafts, approvals, consent and the gatekeeper
- `create_outreach`: one row per (sender, recipient). If the row already exists, it returns the existing one. **This is the duplicate-prevention ledger.**
- `registration(handle, reference, controlled)`: registers a **test recipient**. The person must be in `TEST_RECIPIENT_IDS` (live) or be `fixture_test` (fixture). Consent lasts **7 days**.
- `save_draft`: saves text (1–800 chars), increments `version`, **clears approval**. Uses optimistic locking: if the version you submitted isn't the current one, you get `APPROVAL_STALE`. This catches edits made in another browser tab.
- `snapshot()`: records what an approval covers: sender, recipient, version, purpose version, evidence hashes, consent version.
- `approve`: revalidates evidence, then stores `approved_hash = sha256(draft)` + snapshot.
- **`eligibility()`**: **the main gatekeeper.** It returns a list of reasons sending is blocked:
  `SENDING_PAUSED`, `ACCOUNT_RECONNECT_REQUIRED`, `SENDING_DISABLED`, `HISTORY_ACKNOWLEDGEMENT_REQUIRED`, `RATE_LIMITED`, `ALREADY_CONTACTED` / `SEND_UNKNOWN`, **`RECIPIENT_NOT_ALLOWED`** (not in the test allowlist), `DO_NOT_CONTACT`, **`CONSENT_REQUIRED`**, `RECIPIENT_UNAVAILABLE`, `APPROVAL_STALE`, `EVIDENCE_STALE` (evidence older than 1 hour).
  These reasons appear on the candidate page under **"Sending is blocked"**.
- `suppress`: do-not-contact.

#### `sending.py`: the send itself (the most carefully written part)
`send(rt, oid, expected_version, request_key)`:
1. **Idempotency:** every send button carries a random `request_key`. If that key was already used (a double-click or a page refresh), it returns the previous result instead of sending again.
2. Revalidates evidence.
3. Runs `eligibility()` (a quick pre-check).
4. **History check:** reads the existing DM conversation with that person on X. If you've **already sent them anything**, it blocks with `ALREADY_CONTACTED`.
5. Inside one locked DB transaction it checks:
   - eligibility again and the version again,
   - that the sender has no other send in progress (`SENDER_BUSY`),
   - the daily limit (`DAILY_LIMIT`, default 2/day) and the budget.
   It then creates an `Attempt` row (`in_flight`), sets `account.active_attempt`, and **commits before calling X**.
6. Calls X **once. It never retries.**
7. Records the result:
   - success → `sent`
   - X clearly refused (4xx) → `rejected` (you can fix the problem and try again)
   - timeout, network or 5xx error → **`unknown`**. The sender stays **locked** until someone runs "reconcile". The app would rather never send twice than retry and risk a duplicate.

#### `synchronization.py`: replies and recovery
- `conversation_pages`: pages through the DM history (max 10 pages × 20 = 200 events). It fails safely on errors, missing fields or repeated cursors (`HISTORY_INCOMPLETE`).
- `sync`: imports DM events (deduplicated). If the recipient writes **"STOP"** or "do not contact me", they're automatically added to the do-not-contact list.
- `reply_state`: one of `No confirmed initial send` / `Awaiting reply` / **`Needs attention`** (a reply arrived after the send and hasn't been acknowledged) / `Handled`.
- `acknowledge`: marks the replies seen.
- `recover_stale`: a send stuck `in_flight` for over 120 s (e.g. the server crashed) becomes `unknown`.
- `reconcile`: for an `unknown` send, it searches the DM history for **exactly one** outgoing message with the same text within −5 s/+90 s of the attempt. If it finds one, the send is marked `sent`. Otherwise it stays blocked.

#### `runtime.py`: the switchboard
- `active_account()`: the single connected sender.
- `token()`: decrypts the access token. If it's expiring, it refreshes it safely: it claims the refresh in the DB, makes the HTTP call outside any transaction, then saves the result. If two refreshes happen at once, the second gets `TOKEN_REFRESH_BUSY`.
- `provider()`: gives you `FixtureClient` in fixture mode and `XClient` in live mode. Tests can swap in their own via `provider_override`.
- `read(method, …)`: wraps every X read with **budget reserve → call → settle the actual cost**.

#### `usage.py`
- `reserve()`: under the lock, refuses with `BUDGET_EXCEEDED` if the cap would be exceeded.
- `settle()`: replaces the estimate with the actual cost.

### 5.5 `app/integrations/`

**`x_client.py`**: a thin wrapper over the **official X API v2**:

| Method | Endpoint |
|---|---|
| `me()` | `GET /2/users/me` |
| `user(handle)` | `GET /2/users/by/username/{handle}` |
| `search(query)` | `GET /2/tweets/search/recent` (50 results, author expansion) |
| `posts(ids)` | `GET /2/tweets?ids=…` |
| `events(recipient)` | `GET /2/dm_conversations/with/{id}/dm_events` |
| `send(recipient, text)` | `POST /2/dm_conversations/with/{id}/messages` |

It maps HTTP errors to codes (401 → reconnect, 403 → permission/recipient restricted, 429 → rate-limited with reset time, 402 → credits needed) and **never includes X's raw error text**, so secrets can't leak into the UI.

## 8. ⚠️ Gaps between this build and the assignment (read before submitting)

These are the things an evaluator will likely notice, most important first.

### 🔴 1. In live mode it can only message pre-allowlisted test accounts, never the people it discovers
`eligibility()` blocks anyone not in `TEST_RECIPIENT_IDS` and anyone without a recorded consent. Discovery never adds people to that list. So GenAI Fund **cannot use this to DM the AI/robotics people it finds**, which is the whole point of the tool. The grading rule is *"If we can't use it to run outreach ourselves, it doesn't pass."*

The ground rule ("test real sending only with accounts you control") applies to **your testing**, not to how the product works. **Suggested fix:** add a config flag, e.g. `OUTREACH_POLICY=test_allowlist | operator_approved`. In `operator_approved` mode, any discovered candidate with an approved draft can be sent to. Keep the allowlist as the default for your own testing, and document clearly how GenAI Fund switches it.

### 🔴 2. Nothing has been tested against real X
No OAuth login, real search or real DM has ever run (`docs/VERIFICATION.md` says "blocked"). Real-world problems such as API tier access, DM permissions, encrypted-DM restrictions or wrong response shapes could break it. **You need an X developer account with API credits, plus two X accounts you control, to test before you record the demo.**

### 🟠 3. "Seed accounts" input is missing
The PDF says *"We give it a target segment **or seed accounts**."* Only topic search exists. A simple version would be: enter handles, then look up each user and their recent posts, or the people they follow.

### 🟠 4. "At scale" is very limited
`DAILY_SEND_LIMIT=2`, one send at a time, no bulk approve or queue, 20 people per search. That's fine for safety, but the limits should be configurable and explained as a trade-off in the write-up.

### 🟠 5. The personalisation is weak by default
The template pastes the first 180 characters of someone's post in quotes: *"your public post says: '…'"*. That reads robotic. The Claude adapter is better but untested. Consider making Claude the recommended path, and test it with a real key.

### 🟡 6. The Anthropic API version header looks wrong
`drafting.py` sends `anthropic-version: 2026-10-21`. The documented value for the Messages API is `2023-06-01`. Check the current docs before relying on it. If it's wrong, every model call fails and silently falls back to the template.

### 🟡 7. Docker setup was never run
The "under 15 minutes" setup claim is unverified. Run `docker compose up --build` yourself on a clean machine and time it.

## 9. Glossary

- **Fixture mode**: fake data, so you can demo without X credentials.
- **Idempotency key (`request_key`)**: a random ID attached to each send button. The same key never sends twice.
- **Optimistic locking (`version`)**: every save increments a number. Stale forms get rejected.
- **`SELECT … FOR UPDATE`**: Postgres row lock. Makes two simultaneous actions wait for each other.
- **PKCE / state**: OAuth protections against stolen or forged login callbacks.
- **CSRF token**: a hidden form field that proves a POST came from this app's own pages.
- **Fernet**: symmetric encryption used for stored tokens.
- **Suppression**: the do-not-contact list.
- **Reconcile**: after a send of unknown outcome, look in the DM history to confirm whether it actually went through.
